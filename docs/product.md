# 可感 Palpable 产品文档

> 版本：v0.1（黑客松版）　状态：草案
> 本文只讲做什么、为谁、为什么。怎么做见 [整体架构](architecture.md)，进度见 [路线图](tasks.md)，其余文档见 [文档地图](README.md)。

## 1. 产品定位

**可感（Palpable）是一台以语音为主要交互、外观可被玩偶皮套重新定义的 AI 对讲机。**

硬件核心保持极简：没有复杂按键，没有需要盯着看的屏幕。用户只做三个动作：**贴近、唤醒、说话**。皮套让同一个核心变成不同的"角色"，AI 既是小朋友的陪伴者，也是他和朋友之间的桥梁。

一句话：**不只是玩偶，更是能说话的朋友。**

## 2. 目标用户与场景

主用户是 **6 到 12 岁的儿童**（首发；3–5 岁见 [6.2](#62-商业方案定稿)），付费者是他们的**家长**。产品不限于儿童，但黑客松阶段只深挖这一群体。

| 场景 | 价值 | 说明 |
| --- | --- | --- |
| 日常陪伴 | 有一个会聊天、讲故事、记得"我"的伙伴 | 开箱后由孩子给它起名并认主 |
| 同伴玩耍 | 和朋友用声音连在一起 | 公园、小区、聚会，靠近就成为好友 |
| 出游探险 | 走散也能听见，家长放心 | 区域频道，只和已建立关系的小伙伴互通 |
| 亲情连接 | 外地工作的家长与孩子的桥梁 | 家庭频道，老人和孩子不用学手机 |
| 家庭游戏 | AI 主持的语音游戏 | 故事接龙、猜谜等，轻量多人 |
| 扩展：司机与车队 | 开车时免手持沟通 | 出题方向 B 端延伸，非本期重点 |

## 3. 为什么不是手机或微信语音

评审与用户都会问这个问题。我们的回答是四点，缺一不可：

1. **孩子不需要手机。** 对低龄儿童和老人，一个玩偶就是入口，没有账号、没有界面。
2. **物理入口。** 抱着就能说，靠近就能连，不需要找 App、翻列表。
3. **AI 是群里的成员，不是插件。** 它记得孩子，会陪聊、会主持游戏、会在朋友加入时提醒。
4. **默认安全。** 陌生设备互相屏蔽，好友关系需要家长可控。通用社交软件做不到对儿童的这种默认边界。

## 4. 核心体验

### 4.1 开箱与认主
> 说明：包装盒、开箱动画和"放到桌面"是 **Web 演示的展示行为**，不是设备行为。设备本身只有"第一次上线"之后的部分。

- 设备第一次上线时，由一个叫**小可**的引导精灵自动向孩子打招呼，请他说怎么称呼自己、给伙伴起名字；说完后小可退场，孩子自己的小伙伴用刚起的名字说第一句话。（开箱画面只是演示用来引出这一刻。）
- 家长同意后，小可还会请孩子跟着说一句话，让设备从第一天起就认得这个声音；家长不同意或孩子不想说，直接跳过，不影响使用。
- **认主**＝起名 + 绑定到家长账号。此后设备记得自己的名字和主人，好友与群聊由家长管理。
- 全程语音完成，不需要输入文字。
- 后续版本：做到"只有主人能和这个玩偶说话"，并探索用孩子的音色说话。暂缓的原因见 [架构：设备如何组织](architecture.md#4-设备如何组织)。

### 4.2 免按键对话
- 只有自己和小伙伴时，直接开口就是和它说话；在频道里时，叫小伙伴的名字才是和它说话，其余的话说给好友听。
- 设备拿在手上、挂在身上都能拾取。
- 不需要按住说话（PTT）；对话中孩子可以随时打断。

### 4.3 贴近即连
- 两台或多台设备靠近，通过震动和提示音确认"关联上了"，建立好友关系。
- 套着皮套时更自然：几个玩偶碰在一起，就成了一组。
- 默认贴近即成为好友，不需要家长切到家长端确认；家长端会收到“新朋友”通知，可随时解除。家长可改为“每个新好友都先经家长确认”（服务端配置 `demo.friend_needs_approval`）。

### 4.4 区域语音频道
- 设备检测到孩子进入某个区域（如公园）时，主动询问是否加入当前区域频道。
- 区域按地图区块划分。进入时要孩子同意才加入，离开区块自动退出。
- **只有已建立好友关系的设备才能互相听见**，陌生设备在频道里被屏蔽；好友进入频道时，其他好友会收到提示（"小兔也来公园啦"）。

### 4.5 语音建群与切换
- 说"创建群聊"，设备报出 4 位临时码；朋友说"加入群聊 XXXX"进入。临时码有有效期（本次行程、今天、长期）。
- 说"切到某某群"、"下一个群"、"当前什么群"切换；用灯光颜色、振动和提示音确认结果。
- 多个群后台在线，前台只保留一个当前发言群。

### 4.6 皮套即"可感表面"
- AI 理解语气与状态，硬件用灯光、振动、呼吸感表达"话之外"的情绪。
- 毛绒皮套让振动更柔软，硅胶皮套让灯光透出柔和光晕，硬壳皮套让节奏更清晰。同一个核心，换一个皮套，换一种个性。

### 4.7 画面分享（后续版本）
- 在频道内，孩子让自己的小伙伴**描述眼前的画面**，描述的语音播放给频道里的其他小朋友听，孩子自己也能听见。不是把照片发给别人，而是由小伙伴"讲"出来。
- **私密与公开的边界：** 孩子和自己小伙伴之间的对话是直接外放给孩子本人听，其他人听不见；只有明确在频道内的分享才会被好友听到。
- 分享的画面会记录进历史，家长可在手机端查看。

### 4.8 家长端（微信小程序）
家长端是**只给家长用**的小程序，孩子有手机时也可以使用，但产品核心仍是孩子和玩偶小伙伴之间的直接语音交互，以及和其他小伙伴的语音对话。

- **好友与群聊：** 查看好友列表和所在群聊，确认或解除好友。
- **今日回顾：** 预览今天对讲机聊了什么、遇到了哪些小朋友、分享了什么风景。
- **家长控制：** 屏蔽、解除好友、查看对话摘要。
- **黑客松阶段：** 为了快速实现 MVP，用 **Web 页面模拟手机窗口** 来展示家长端，不做真实小程序。

## 5. 儿童隐私与安全（产品承诺）

| 承诺 | 做法 |
| --- | --- |
| 陌生人无法接触孩子 | 未建立好友关系的设备，音频不转发，也不出现在对方的在线列表 |
| 家长可控 | 新好友默认贴近即生效并通知家长（可改为先经家长确认）；家长通过小程序查看好友、群聊、对话摘要和分享记录；可随时屏蔽或解除好友 |
| 声纹最小化 | 只保存声纹特征与绑定关系，不长期保留原始音频；删除设备同时删除声纹。例外：引导对话的音频在灵矽侧保留（约 60 天）用于登记声纹 |
| 内容友好 | AI 对话使用儿童友好语气，不诱导孩子透露地址、学校、电话等个人信息 |
| 数据留在服务端规则内 | 好友、频道、屏蔽等规则全部由服务端裁决，设备端无法绕过 |

合规提示（上线前必须落实，不属于黑客松演示范围）：未成年人的声纹属于敏感个人信息，需要监护人单独同意；需要明确的数据保存期限与删除机制；面向儿童的 AI 内容需要审核与过滤。

## 6. 商业价值与商业模式

> 本节的数字与比例均为**待验证假设**，用来说明商业逻辑的结构，不是已有数据。验证路径见 [6.6](#66-验证路径)。

### 6.1 解决什么问题，对谁有价值

| 角色 | 痛点 | 可感给的价值 |
| --- | --- | --- |
| 孩子（6–12 岁） | 没有手机，想和小伙伴说话只能靠大人转接；身边缺一个"记得我"的陪伴者 | 抱着就能说、靠近就能连；小伙伴记得名字与喜好，也能在朋友之间搭桥 |
| 家长（付费者） | 不想过早给手机；通用社交软件没有儿童边界；放孩子出去玩又不放心 | 默认只和好友互通、陌生人屏蔽；好友与回顾可查可控；走散也能听见 |
| 团体组织者（B 端） | 夏令营、研学、亲子活动要随时联络一群孩子，对讲机没有安全边界与内容友好 | 同一套"频道 + AI"，按席位使用，区域频道与好友规则开箱即用 |

核心判断：**需求不是"又一个会聊天的玩具"，而是"让不用手机的孩子安全地和朋友连在一起"。** AI 陪伴吸引孩子，连接与安全才让家长愿意持续付费。

### 6.2 商业方案（定稿）

> 定价与目标均为**假设**，用于路演与试点设计；成本与转化数据到位后修订。依据见 [6.7](#67-市场与竞品调研) 与 [research.md](research.md)。

**一句话：** 硬件近成本价做入口，皮套与内容包做持续消费，家庭会员做主要利润；首发面向 6–12 岁，用夏令营、研学和亲子活动做试点渠道。

**1. 首发人群与定位**

| 决策 | 内容 | 原因 |
| --- | --- | --- |
| 首发年龄 | **6–12 岁**，主力 6–10 岁 | 专家建议 5 岁及以下不使用 AI 玩具（[Common Sense Media](https://www.commonsensemedia.org/research/ai-in-the-toy-box-how-parents-view-ai-enabled-toys-for-young-children)）；6 岁以上孩子开始有同伴社交需求，也还没到给手机的年纪 |
| 3–5 岁 | 后续版本，只开放好友 / 家庭对讲，不开放 AI 开放式对话 | 规避内容安全与监管风险 |
| 付费者 | 家长 | 孩子是用户，家长是买单人与管理者 |
| 产品定位 | **「孩子之间的无屏语音桥梁」**，AI 是陪伴者与桥梁，不是替代朋友 | 多数家长不希望 AI 当孩子的朋友（同上），也避开与「AI 陪伴玩具」的红海正面竞争 |

**2. 产品线与定价假设**（人民币，含税；参考价位见 [research.md §6–7](research.md#6-皮套与持续消费)）

| 产品 | 定价 | 角色 |
| --- | --- | --- |
| 可感核心（含一款皮套） | ¥299 | 入口。目标毛利不低于 BOM + 渠道成本；不靠硬件赚钱 |
| 皮套（单件） | ¥69–99 | 复购。四款基础皮套 + 节日款 / 联名款 |
| 家庭套装（三件皮套） | ¥229 | 一户多孩 / 与朋友一起买，带动好友图谱 |
| 可感+ 家庭会员 | ¥19 / 月，¥168 / 年 | 主要利润 |

可感+ 的权益划分：

| | 免费 | 可感+ |
| --- | --- | --- |
| 好友对讲、区域频道、4 位码群聊 | ✓（不耗 AI 成本，不设限） | ✓ |
| 家长端：好友确认与解除、今日回顾 | ✓ | ✓ |
| 与小伙伴 AI 对话 | 每日约 10 分钟 | 每日更长（设上限，成本可控） |
| 云端记忆（小伙伴长期记得孩子） | — | ✓ |
| 故事与游戏内容包 | 试用 | ✓ |
| 更多好友与群 | 基础数量 | 更多 |

原则：**连接与安全永远免费**，AI 增强才收费。这样安全不是付费墙，也让孩子的社交图谱不被订阅卡住；同时比「不订阅功能受限」的竞品更好讲。续费须有提前提醒和一键取消。

**3. 渠道**

| 渠道 | 角色 | 阶段 |
| --- | --- | --- |
| 夏令营、研学机构、亲子活动 | **试点与获客**：设备按活动租赁，试点期免费换取数据与案例，不设价格；孩子在活动里成为好友，家长回头买 | 试点 |
| 线上预售与社交媒体 | 家长教育与首批销售；以「默认安全」「孩子之间的连接」为内容 | 试点后 |
| 联名 IP / 线下体验点 | 放大皮套复购与品牌 | 规模化 |

B 端不是主要收入来源，是低成本获客与产品验证渠道；按席位收费等试点出价格再定。

**4. 路线与门槛**

| 阶段 | 做什么 | 进入下一阶段的门槛（目标，非预测） |
| --- | --- | --- |

### 6.3 为什么单位经济有机会成立

成本结构由架构决定，不是事后优化：

1. **孩子之间的对讲不经过 AI。** 好友语音是设备 → 服务端转发 → 好友设备（见 [D2](architecture.md#2-关键决策)），只消耗带宽，不产生语音识别、大模型与语音合成的费用。**越多孩子互相说话，边际成本越低，而产品价值（连接）越高。**
2. **AI 成本只发生在"对小伙伴说话"时。** 可以按会员等级设置每日对话时长上限，成本可控、可定价。
3. **智能体数量与皮套款数相当，不随用户数增长**（[D3](architecture.md#2-关键决策)）；记忆按设备隔离，新增用户不新增智能体。
4. **设备端没有业务逻辑。** 固件只实现一份协议，新规则与新玩法通过服务端发布，不需要召回硬件，也让会员功能可以持续上新。

用一个**示意**算法说明结构（数字仅为占位，需用真实成本替换）：

```
单设备月毛利 ≈ 会员月费 − AI 对话成本 − 带宽与存储成本 − 渠道与支付成本
AI 对话成本  ≈ 日均对话分钟数 × 30 × 每分钟 AI 成本    （受会员等级的时长上限约束）
```

硬件按接近成本定价，会员订阅覆盖 AI 成本后形成持续毛利，皮套与内容包提高单用户总价值。

### 6.4 获客与增长

- **网络效应：** 好友关系是产品价值的来源——孩子想和谁说话，就会让那个孩子也有一台。一台设备的价值随好友数增加，天然带来家庭间的口碑传播。
- **线下场景：** 公园、小区、亲子活动与夏令营是"贴近成为好友"的发生地，适合做体验点与团购。
- **家长信任：** 默认安全、可查可控是推荐给其他家长的理由，也是对"儿童社交"最大的顾虑的直接回答。
- **皮套与 IP：** 联名款与节日款拉动二次购买与社交媒体传播。

### 6.5 壁垒与护城河

| 壁垒 | 内容 |
| --- | --- |
| 默认安全的规则引擎 | 好友、频道、屏蔽、家长控制全部由服务端裁决且有单一执行点（[架构 §8](architecture.md#8-隐私规则的执行点)），竞品用 App 补丁很难做到同等边界 |
| 好友图谱 | 孩子之间的真实关系是迁移成本；换设备不换朋友 |
| 同一内核、多种个性 | 皮套 + 风格智能体的组合让内容与 IP 合作可以低成本扩品 |
| 协议化的设备抽象 | 设备端只实现一份协议，Web 模拟器与固件同源；换硬件方案、做小程序、做车载版时服务端基本不动 |
| 数据与记忆 | 小伙伴对孩子的记忆随使用积累，是留存与订阅续费的依据（在隐私承诺范围内） |

### 6.6 验证路径

| 假设 | 验证方式 | 通过的信号 |
| --- | --- | --- |
| 家长愿意为"陪伴 + 安全"买单 | 用户访谈、预售页、小批量试销 | 预售转化率；对订阅价格的接受度 |
| 孩子之间会互相对讲，而不只是对 AI 说话 | 夏令营 / 小区试点 | 好友对讲时长占比（见[成功指标](#10-成功指标假设)）；人均好友数 |
| AI 成本能被会员覆盖 | 试点期记录每设备每日 AI 对话分钟数 | 单设备月 AI 成本低于会员月费的一部分，留足毛利 |
| 家长确认与屏蔽规则是低负担的 | 观察家长端使用 | 好友通知的响应时间；解除好友的比例 |
| B 端有付费意愿 | 与 1–2 家夏令营 / 研学机构做活动试点 | 按活动或席位的付费意向 |

意义：家长愿意为儿童联系类硬件付费，且「社交」是核心卖点；高价位段增长最快，说明溢价空间存在。可感的定位是**不带屏幕、不上手机生态的替代方案**，需要验证它能否从手表的用户里分走一部分。

**商业模式先例：硬件 + 持续消费**

| 公司 | 事实 | 来源 |
| --- | --- | --- |
| Tonies（儿童音频盒） | 2025 年收入 6.303 亿欧元（+31%）：盒子 1.61 亿、角色卡 4.47 亿，角色卡约占 74%；全年售出约 260 万台盒子、4330 万个角色卡；调整后 EBITDA 率 8.6% | [公司新闻稿](https://www.mynewsdesk.com/us/tonies/pressreleases/tonies-continues-profitable-growth-with-record-results-in-2025-expects-strong-momentum-for-full-year-2026-expansion-of-ecosystem-around-toniebox-2-proves-a-global-success-3442746)、[Spielwarenmesse](https://www.spielwarenmesse.de/en/mag/toy-market-news/tonies-profitable-growth-with-record-results-in-2025/) |

| Relay（美国儿童无屏对讲机，Republic Wireless / Relay） | 早期报道：设备 49.99 美元 + 每月 9.99 美元服务费；报道为 2019 年前后，**现价需到官网核实** | [Macaroni Kid](https://aurora.macaronikid.com/articles/5d5b75260fdde975e5654832/relay_-the-alternative-to-cell-phones-for-kids) |

意义：
1. 「无屏幕 + 家长可控」的儿童设备已被市场验证，收入主要来自**持续消费品**（角色卡，对应可感的皮套 / 内容包）而不是首次硬件。Tonies 盒子与角色卡的年销量比约 1 : 17，但这是年度销量比，不是单用户购买比。
2. 儿童无屏对讲 + 月费有先例（Relay），但它没有 AI，也没有「陌生人屏蔽、好友需家长可控」这一层。
3. 硬件 + 内容的利润率并不高（Tonies 调整后 EBITDA 率个位数），说明**订阅 / 内容的毛利要靠规模与 AI 成本控制**，不能想当然。

### 6.8 对产品与路演的启示

| 调研发现 | 对可感意味着什么 | 动作 |
| --- | --- | --- |
| 家长高度担心数据收集（>80%），且多数不希望 AI 当「朋友」 | 可感的定位是「孩子之间的桥梁」，AI 是陪伴者 + 桥梁，不是替代朋友；这和家长偏好一致 | 对外表述强调「连接孩子与朋友」；隐私承诺单列成节（[§5](#5-儿童隐私与安全产品承诺)） |
| Common Sense 建议 5 岁及以下不用 AI 玩具 | 目标用户 3–12 岁与这条建议冲突 | **需要决策**：首发聚焦 6–12 岁，或把低龄版本做成只有好友对讲、不开放 AI 开放式对话 |
| AI 玩具安全事件集中在内容失控 | 提示词之外还要有内容安全兜底 | 路线图补「内容审核与过滤」，上线前做第三方红队测试 |
| 内容 / 配件才是 Tonies 的主要收入 | 皮套与内容包是核心收入假设，需要验证复购 | 试点中记录皮套复购与内容包转化 |
| 硬件 + 内容公司利润率不高 | 毛利要靠 AI 成本控制：好友对讲不走 AI，且设会员对话时长上限 | 试点记录每设备 AI 对话分钟数 |
| 儿童手表市场大、高价位增长快 | 家长为社交 + 安全付费，但手表是带屏、绑手机生态的产品 | 用户访谈验证「无屏幕对讲」能否替代 / 补充手表 |

**还没查到的**（路演前建议补）：中国对儿童个人信息与声纹的具体合规要求（《个人信息保护法》《儿童个人信息网络保护规定》等的条文）、国内 AI 玩具的订阅定价与付费率、可感的目标价位下的真实 BOM 成本。

## 7. 与现有产品的差异

| 类别 | 代表 | 我们的差异 |
| --- | --- | --- |
| 传统/公网对讲机 | 公网对讲机、车载对讲 | 它们面向专业场景，有定位调度但没有对儿童的陪伴与安全边界 |
| 对讲类 App | Voxer 等 | 需要手机和账号，不适合低龄儿童；AI 为附加功能 |
| 桌面 AI 伴侣设备 | Loona 等 | 偏单机陪伴，没有"朋友之间的桥梁"这一层 |
| 儿童无屏对讲 | Relay | 已验证「无屏幕 + 月费」，但没有 AI，也没有陌生人屏蔽与家长可控的好友规则 |
| 儿童音频盒 | Tonies、Yoto | 验证了「硬件 + 持续内容」的收入结构；单向内容播放，没有孩子之间的连接 |
| 儿童电话手表 | 小天才等 | 家长为联系 + 定位 + 社交付费的成熟市场；带屏、绑手机生态，社交与安全边界依赖厂商 App |
| 通用社交 | 微信语音 | 没有儿童默认安全边界，也没有物理入口与 AI 成员 |

> 以上对比基于一轮公开资料的快速调研，立项前需要补查更多竞品（如 Zello、国内对讲厂商）。

## 8. 黑客松演示范围

演示由 Web 页面模拟设备：**一个页面就是一台设备的客户端**（一个小朋友、一只玩偶），第一人称在 3D 世界里体验；想要第二个小朋友，就再开一个页面。家长端是另一个页面（`#/parent`）。主线以 [AGENTS.md](../AGENTS.md#演示约束) 为准：

官网首页（`#/`）以湖畔公园和四只毛绒伙伴介绍产品，提供产品特点、使用场景与安全说明；“观看演示”进入设备模拟器（`#/play`），家长端入口单独保留。首页插画仅作产品展示，不连接设备，也不申请麦克风权限。

1. **开箱（Web 展示）：** 站在房间里，走到盒子旁点开盒盖，把玩偶抱出来，放到桌子上的小圈圈里，它就醒了。
2. **命名认主：** 玩偶第一次上线，向小朋友问好，请他起名；麦克风默认打开，开口就能对话，不需要按任何键；灯带随状态变化。
3. **公园区域频道：** 抱着玩偶走到门口出门，来到公园（第一人称），小伙伴问要不要加入公园频道，孩子同意后加入。同一频道里的非好友互相听不见，头顶标注"已屏蔽"。
4. **贴近成为好友：** 两个小朋友在公园里走到一起，振动与提示音确认，建立好友关系。
5. **好友互相听见：** 好友说话，对方设备播放；好友进入频道时收到提醒。

加演（时间允许）：家长端 Web 手机窗口，展示好友列表与今日回顾。是否纳入主线见 [开放问题](architecture.md#11-开放问题)。

不在演示范围：真实硬件、皮套材质效果的物理验证、声纹认主、画面分享、司机与车队场景、真实的微信小程序。

## 10. 成功指标（假设）

黑客松阶段以"演示跑通 + 评委能讲清商业逻辑"为目标。产品化后建议关注：

- 首次开箱到完成命名认主的完成率与耗时。
- 日活孩子数、人均对话轮数、人均好友数。
- 好友之间的对讲时长占比（衡量"桥梁"价值，而非单纯陪聊）。
- 家长确认好友的通过率与响应时间。
- 皮套复购率与会员订阅转化率。

## 11. 风险与待验证

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 儿童隐私合规 | 声纹与语音数据敏感 | 默认最小化存储，监护人同意流程，上线前法务评估 |
| 免按键误触发 | 常开麦克风易误唤醒、串音 | 唤醒词加人声门限；频道内对讲机式发言权，同一时刻只转发一人 |
| 区域频道骚扰 | 陌生人频道有内容风险 | 本产品默认只在好友间互通，不做公共陌生人频道 |
| 付费意愿 | 家长是否为陪伴 + 安全付费 | 用户访谈、预售验证 |
| 竞品与替代 | 儿童手表、早教机已占心智 | 突出"可换皮套 + 朋友之间的桥梁 + 默认安全" |
| AI 玩具内容安全事件 | 2025 年已有 AI 玩具被测出输出不适宜内容并被模型供应商切断（见 [6.7](#67-市场与竞品调研)） | 内容审核与过滤、第三方红队测试；规则在服务端而不只靠提示词 |
| 低龄用户与专家建议冲突 | Common Sense Media 建议 5 岁及以下不用 AI 玩具 | 决策：首发聚焦 6–12 岁，或低龄版本只开放好友对讲 |
| 技术：浏览器音频 | WebCodecs 仅 Chromium 系支持 | 演示限定 Chrome / Edge；硬件落地后不受影响 |
