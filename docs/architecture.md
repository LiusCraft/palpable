# 可感 Palpable 整体架构

> 本文回答三个问题：**系统由哪些部分组成、各部分怎么说话、一条语音是怎么走的**。
> 细节在别处：[产品文档](product.md)（做什么）、[模块规格](modules.md)（每个模块的职责与接口）、[灵矽对接](linx-integration.md)、[设备协议](../protocol/README.md)、[任务包](tasks.md)。

## 1. 系统边界

```
  ┌────────────┐   WebSocket：JSON 控制消息 + Opus 音频帧        ┌────────────────────────────┐
  │ 设备        │ ─────────────────────────────────────────────▶ │                            │
  │ Web 模拟器  │ ◀───────────────────────────────────────────── │                            │   WebSocket + REST
  │ （未来：固件）│                                                │         palpabled          │ ───────────────▶ ┌──────────┐
  └────────────┘                                                │      （一个 Go 进程）        │ ◀─────────────── │ 灵矽      │
  ┌────────────┐   REST                                         │                            │                  │ 听说·记忆  │
  │ 家长端      │ ─────────────────────────────────────────────▶ │                            │                  │ 视觉·MCP  │
  │ Web 手机窗口│                                                 │                            │                  └──────────┘
  │ （未来：小程序）│                                              └─────────────┬──────────────┘
  └────────────┘                                                              │
  ┌────────────┐   WebSocket（只读）                                       ┌─────▼─────┐
  │ 演示地图    │ ◀──────────────────────────────────────────────────────── │  SQLite    │
  └────────────┘                                                          └───────────┘
```

- **设备**是传感器和执行器：采集声音、播放声音、灯光、振动、感知靠近与位置。**不含任何业务判断。**
- **palpabled** 是唯一的后端进程，承载全部业务：谁是好友、谁在哪个频道、声音去给谁、设备怎么开通。
- **灵矽**是外部服务，提供小伙伴的"大脑"：听与说、记忆、看图片、工具调用。可感只和它的 WebSocket 与 REST 打交道。
- **家长端**与**演示地图**不是设备，不进设备协议，各走自己的接口。

## 2. 四个关键决策

1. **设备只连我们的后端，不直连灵矽。** 灵矽的令牌只在服务端；固件只需实现我们的设备协议。后端替每台设备维护一条到灵矽的会话。
2. **声音有两条通路，由 `voice` 模块决定走哪条。** 对 AI 说话：设备 → 后端 → 灵矽，回答只放给自己听。对好友说话：设备 → 后端 → 好友设备，不经过 AI。规则见 [voice](modules.md#3-voice)。
3. **灵矽智能体就是小伙伴的"大脑"。** 设备以自己的 MAC 上线，后端按外观自动选定风格智能体并开通；记忆、声纹、视觉都用灵矽的。设备端工具（灯光、振动、拍照）与后端业务工具（建群、切群）由网关合并成一份设备端 MCP 工具列表给 AI。
4. **设备行为要能在固件上复现，Web 展示只在演示里存在。** 开箱动画、公园场景、地图、家长手机窗口是 Web 展示，不进协议；协议里只有设备真的会做的事。

## 3. 分层与依赖规则

```
接入层     gateway                          设备连接、握手、会话；只认"这是哪台设备"
              │
能力层     voice   bridge/linx   bridge/mcp  声音往哪走；与灵矽对话；工具代理
              │            │          │
领域层     channel  relation  zone  device  history  share   业务规则与状态
              │
基础层     store   linxapi                  持久化；灵矽 REST
```

**依赖只能向下，不能向上。** 领域层不知道有 WebSocket，也不知道声音是什么；能力层把设备事件翻译成对领域层的调用。两条硬规则：

- **`voice` 是唯一决定声音去向的地方**，`channel` 只回答"谁在哪个频道"，`relation` 只回答"是不是好友"；`bridge` 不得绕过 `voice` 转发音频。
- **业务规则只在领域层。** 设备、`bridge/mcp` 的工具、家长端接口都只是进入领域层的不同入口，不拥有规则。

## 4. 三条关键时序

### 4.1 设备上线与自动开通

```
设备              gateway        device         linxapi       bridge/linx       灵矽
 │ hello(MAC,skin) │               │               │               │               │
 │────────────────▶│  Ensure(info) │               │               │               │
 │                 │──────────────▶│ 无档案？       │               │               │
 │                 │               │ 按 skin 选风格 │               │               │
 │                 │               │ PreregisterDevice(agent, MAC) │               │
 │                 │               │──────────────▶│──────────────────────────────▶│
 │                 │◀──────────────│ 档案已建       │               │               │
 │◀ hello.ack ─────│               │               │ 以 MAC 拨号    │               │
 │◀ audio.downlink │               │               │──────────────────────────────▶│
 │                 │               │               │               │◀── hello ──────│
 │◀ light/Say 问候 ─│◀──────────────┴───────────────┴───────────────│               │
```

开通失败时设备收到 `error`，但仍可进频道对讲（对讲不依赖 AI）。

### 4.2 对 AI 说话

```
设备 ──音频帧──▶ gateway ──▶ voice（判定路由=AI）──▶ bridge/linx ──音频──▶ 灵矽
设备 ◀──音频帧── gateway ◀── bridge/linx ◀──────────── TTS 音频 ◀───────── 灵矽
                                 │ stt/tts 状态 → 灯光 light 与 speaker.state
```

不在频道时一直走这条；在频道里需要先 `wake`（叫小伙伴的名字）才走这条，一个回合后回到频道。

### 4.3 在频道里和好友说话（含陌生人屏蔽）

```
小朋友 A                voice                 channel      relation        小朋友 B（好友）   小朋友 C（陌生人）
  │ mic.state start+音频帧 │                      │            │                   │                  │
  │───────────────────────▶│ 抢到发言权            │            │                   │                  │
  │                        │ Members(频道) ───────▶│            │                   │                  │
  │                        │◀──────── [A, B, C]───│            │                   │                  │
  │                        │ AreFriends(A,B)? ────────────────▶│ 是                │                  │
  │                        │ AreFriends(A,C)? ────────────────▶│ 否 → 丢弃，不转发  │                  │
  │                        │── speaker.state(peer, from=A) ───────────────────────▶│                  │
  │                        │── Opus 帧（每听者独立有界队列）─────────────────────────▶│  C 什么也收不到    │
```

同一频道同一时刻只有一个人说话（对讲机式），好友说话会打断正在播的 AI 语音。

## 5. 设备抽象

Web 模拟器与固件各自实现下面七项，其余全在服务端。

| 能力 | 方向 | Web 模拟 | 未来硬件 |
| --- | --- | --- | --- |
| `mic` 麦克风音频 | 设备→服务端 | WebAudio + Opus 编码 | I2S 麦克风 + Opus |
| `speaker` 扬声器音频 | 服务端→设备 | WebAudio 解码播放 | I2S 功放 |
| `light` 灯带 | 服务端→设备 | 3D 发光材质 | LED 灯带 |
| `haptic` 振动 | 服务端→设备 | 玩偶抖动 + 提示音 | 振动马达 |
| `proximity` 靠近发现 | 设备→服务端 | 由地图中的距离生成 | BLE / NFC 扫描 |
| `location` 定位 | 设备→服务端 | 地图中的坐标 | GPS |
| `wake` 唤醒事件 | 设备→服务端 | 点击玩偶或语音唤醒 | 本地唤醒词引擎 |

## 6. 运行形态

- **后端：** 一个 Go 进程 `palpabled`，监听 `/ws`（设备）、`/world`（演示地图，只读）、`/api`（家长端）。
- **前端：** Vite 构建的静态页面，开发期把 `/ws` 代理到后端。
- **外部依赖：** 灵矽（WebSocket + REST，令牌来自环境变量）；SQLite 文件。
- **多设备演示：** 同一页面可开多个"小朋友窗口"，每个是独立的虚拟设备；也可多个浏览器分别接入。

## 7. 演示主线对应的模块

| 步骤 | 触发 | 走过的模块 |
| --- | --- | --- |
| 开箱（Web 展示） | 点击盒子 | `scenes/unbox` |
| 上线开通与问候 | 设备 `hello` | `gateway` → `device` → `linxapi` → `bridge/linx` |
| 起名 | 孩子说名字 | `bridge/linx` → `device` |
| 陪伴对话 | 不在频道时说话 | `voice`（路由 AI）→ `bridge/linx` |
| 进入公园 | `location` 上报 | `zone` → `channel` |
| 陌生人屏蔽 | 同频道的非好友 | `voice` + `relation` |
| 贴近成为好友 | `proximity` 上报 | `relation` |
| 好友互相听见 | 好友说话 | `voice` → `channel` + `relation` |
| 家长看回顾 | 家长端请求 | `parentapi` → `history` |

## 8. 里程碑

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| M0 | 骨架：协议、网关、Web 设备模拟器 | ✅ |
| M1 | 设备经后端与灵矽对话，灯带随状态变化（含对接修正） | ✅ |
| M2 | 设备自动开通（风格智能体）、开箱与起名 | ⬜ |
| M3 | 语音主线：公园频道、好友、陌生人屏蔽、好友互相听见 | ⬜ |
| M4 | 画面分享、今日回顾与家长端、设备端 MCP 工具、文案与提示音 | ⬜ |

各阶段对应的任务见 [tasks.md](tasks.md)。

## 9. 风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 灵矽联调未做 | 握手、消息格式按源码与文档推断，没连过真实服务 | 最先拿到令牌联调，见 [linx-integration.md](linx-integration.md) 的待验证项 |
| 浏览器音频 | 依赖 WebCodecs，仅 Chromium 系；24kHz 解码效果未听过 | 演示限定 Chrome / Edge；联调时实测 |
| 多人语音延迟 | 目标端到端 < 300ms，尚无实测 | 每个发言记录首帧进出时间戳，早测早改 |
| 儿童隐私 | 语音与声纹敏感 | 陌生人默认屏蔽；声纹与原始音频不入库；上线前合规评估 |
