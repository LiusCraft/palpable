# 可感 Palpable 整体架构

> 本文回答：**系统由哪些部分组成、依赖怎么走、设备怎么组织、一条语音怎么走、隐私规则在哪里执行。**
> 模块接口见 [模块设计](modules/README.md)，进度见 [tasks.md](tasks.md)，术语见 [文档地图](README.md#术语表)。

## 1. 系统边界

```
  ┌──────────────┐  /ws   JSON 控制消息 + Opus 音频帧      ┌──────────────────┐  WebSocket + REST  ┌────────────┐
  │ 设备          │ ◀────────────────────────────────────▶ │                  │ ◀────────────────▶ │ 灵矽        │
  │ Web 模拟器    │                                        │    palpabled     │                    │ 听说 · 记忆 │
  │（将来：固件）  │                                        │  （一个 Go 进程） │                    │ 声纹 · 视觉 │
  └──────────────┘                                        │                  │                    └────────────┘
  ┌──────────────┐  /api  REST                            │                  │
  │ 家长端        │ ─────────────────────────────────────▶ │                  │
  │ 微信小程序    │                                        │                  │
  │（演示：Web）  │                                        └────────┬─────────┘
  └──────────────┘                                                 │
  ┌──────────────┐  /world  WebSocket，只读，仅演示模式             ┌──▼─────┐
  │ 演示地图      │ ◀─────────────────────────────────────────────  │ SQLite │
  └──────────────┘                                                 └────────┘
```

- **设备**是传感器和执行器：采集与播放声音、灯光、振动、感知靠近与位置。**不含任何业务判断。**
- **palpabled** 是唯一的后端进程，承载全部业务：谁是好友、谁在哪个频道、声音去给谁、设备怎么开通。
- **灵矽**是外部服务，提供小伙伴的"大脑"。能力与限制见 [linx-integration.md](linx-integration.md)。
- **家长端**与**演示地图**不是设备，不进设备协议，各走自己的接口。演示地图会暴露所有设备的位置，**只在演示模式下开启**。

## 2. 关键决策

| # | 决策 | 原因 | 代价 |
| --- | --- | --- | --- |
| D1 | **设备只连我们的后端，不直连灵矽。** 后端替每台在线设备维护一条到灵矽的会话 | 令牌不出服务端；固件只需实现一套协议；屏蔽等规则能在中间裁决 | 音频多一跳；后端要管理上游连接与重连 |
| D2 | **声音去向只由 `voice` 决定。** 对 AI 说话：设备 → 后端 → 灵矽，回答只给自己听；对好友说话：设备 → 后端 → 好友设备，不经过 AI | 陌生人屏蔽只有一个执行点，便于审计与测试 | `voice` 是热点模块，接口要先定稳 |
| D3 | **按皮套共用风格智能体。** 设备以自己的 MAC 上线，后端按 `skin` 自动选定风格智能体并在灵矽注册 | 开通零配置；智能体数量只和皮套款数相当 | 声纹"只认主人"做不到（灵矽里是智能体级配置），见 [§4](#4-设备如何组织) |
| D4 | **业务工具走设备端 MCP 代理，不做云端 MCP。** 网关把设备自带工具与业务工具合并成一份列表给 AI | 调用身份天然来自连接，不需另做鉴权；不依赖灵矽控制台配置 | 网关要解析并合并 MCP 消息；云端方案留作 [备选](linx-integration.md#备选云端-mcp) |
| D5 | **设备行为与 Web 展示分开。** 协议里只有设备真的会做的事；开箱动画、公园、地图、手机窗口只在 Web | 保证 Web 模拟器换成固件时服务端不用改 | 演示里的一些画面需要另走 `/world` 等非设备通道 |
| D6 | **频道成员按"参与者"建模。** 设备 `dev:<mac>` 与小伙伴智能体 `agt:<mac>` 平级 | 小伙伴进频道时没有改频道、好友与 voice 的转发规则 | 多一层 `ParticipantID` 类型；小伙伴的音频要从主人的 AI 下行里分流，见 [§6](#6-小伙伴智能体作为频道成员) |
| D10 | **设备认证用每台设备一把 P-256 密钥的挑战应答，服务端只存公钥** | 伪造 MAC 不能再冒充别人的设备；库泄露也不能签名；不依赖设备时钟 | 每次握手多一个来回；固件要保管私钥（Flash 加密），见 [trust.md §2](trust.md#2-设备身份与认证) |
| D11 | **家长先绑定，设备才提供服务**；绑定用设备播报的 6 位短码 | 陪伴类 AI 对不满 14 岁的孩子须先取得监护人同意；短码证明家长就在设备旁边 | 开箱多一步；演示用 `demo.guardian` 自动绑定跳过，见 [trust.md §3](trust.md#3-绑定家长先开通孩子再认主) |
| D12 | **交朋友两关：两个孩子当面说"好"，两家监护人各自放行** | 回应"默认交友"的质疑，贴近陌生人社交监管取向；每家可为自家孩子放宽 | 演示需预置"孩子自己交友"才能一步成为好友，见 [trust.md §4](trust.md#4-交朋友) |
| D13 | **家长端用微信登录换服务端自签的不透明会话令牌**（随机 32 字节，库里只存哈希，30 天到期后静默重登），不用 JWT、不存 `session_key` | 退出与注销能立即作废令牌；库泄露拿不到可用令牌；只收 openid，最少收集 | 每个请求查一次库；以后加 App 或网页端要另接登录方式，只需再实现 `Auth`，见 [account](modules/account.md) |
| D14 | **厂家后台是独立进程、独立数据库，与 palpabled 只通过窄接口交互**：palpabled 开放 `/internal/devices/*`（登记公钥、擦除、吊销、锁定），后端回推绑定/解绑事件，家长标识只以 HMAC 值出现 | 厂家运营人员不接触孩子数据；两边可分别部署、分别授权；后台宕机不影响孩子使用 | 多一个进程与一套账号；擦除等动作依赖 palpabled 在线，离线时被明确拒绝而不是跳过，见 [factory.md](factory.md) |
| D7 | **领域层只发事件、不发设备消息。** 下行的 `channel.state`、`friend.state` 等由编排层 `app` 订阅事件后翻译 | 领域层不知道 WebSocket，可用假实现单测；协议变化不波及业务规则 | 多一个编排模块，事件需要有序投递 |
| D8 | **新设备先由系统级"引导智能体"接待，起名后交棒给风格智能体。** 引导智能体不属于任何皮套，只服务 `stage` 未完成的设备：欢迎、请孩子起名、（经监护人同意后）采集一段声音登记声纹 | 孩子的名字和声音在第一句话就能拿到；风格智能体从第一次对话起就认识孩子，提示词不必再兼顾"初次见面"；引导流程可独立迭代 | 交棒要切换智能体并重连灵矽会话；记忆容器在交棒时才建立，引导期的对话不迁移；多一份提示词与音色要维护 |
| D9 | **ESP32 复用小智的板级驱动，应用层实现可感协议。** 固定上游提交后生成硬件源码树，以 `firmware/main/` 替换应用层，保留配网、编解码与本地唤醒 | 支持现有小智硬件，设备与 Web 共用服务端协议；避开小智云激活与另一套对话状态机 | 需维护上游适配补丁；每个板型及 GPS / BLE / NFC 传感器仍需单独接线与验收，见 [固件说明](../firmware/README.md) |

## 3. 分层与依赖

```
接入层   gateway（/ws 设备）     parentapi（/api 家长）     world（/world 演示）
              │ Handler
编排层   app            分发设备消息；订阅领域事件并下发设备消息；实现各模块声明的端口
              │
能力层   voice          bridge/linx          bridge/mcp
              │
领域层   device   relation   channel   zone   history   share   account
              │
基础层   store    linxapi    wechat    protocol   id
```

**依赖规则**

1. **只能向下依赖。** 同层依赖必须无环，并在对应[模块文档](modules/README.md)的"依赖"里写明。接入层之间不互相调用。
2. **需要向上做事时，由下层声明端口。** 比如 `voice` 要给设备发音频，就声明 `Sink` 接口，`app` 用 gateway 会话实现并注入；`voice` 不 import gateway。
3. **`voice` 是唯一决定声音去向的地方。** `channel` 只回答"谁在哪个频道"，`relation` 只回答"是不是好友"；`bridge` 不得绕过 `voice` 转发音频。
4. **业务规则只在领域层。** gateway、parentapi、bridge/mcp 的工具、app 都只是入口与编排。判断方法：一段 `if` 里出现"好友 / 频道 / 家长 / 开通"，它就应该在领域层。

**端口一览**（由 `app` 在启动时组装）

| 端口 | 声明方 | 实现方 | 用途 |
| --- | --- | --- | --- |
| `Sink` | voice | gateway 会话（将来：智能体的灵矽会话） | 向参与者发消息与音频 |
| `AI` | voice | bridge/linx | 把音频交给 AI、打断 AI |
| `Membership`、`Friends` | voice | channel、relation | 计算听者 |
| `DeviceLink` | bridge/linx | gateway 会话 | 向设备下发灯光、`speaker.state` 与 TTS 音频 |
| `Announcer` | share | bridge/linx 的 `Say` | 让小伙伴对某台设备说一句话 |

## 4. 设备如何组织

**身份就是 MAC。** 真实设备用自己的 MAC；Web 模拟器首次打开时生成一个并存在浏览器里。设备连上后端时在 `hello` 里自报 MAC 与 `skin`，后端据此自动开通，不需要人工配置。

**风格智能体与皮套一一对应：**

| skin | 风格智能体 |
| --- | --- |
| `dragon` | 小龙 |
| `rabbit` | 兔兔 |
| `bear` | 小熊 |
| `cat` | 小猫 |

每种风格有自己的系统提示词与音色。服务端启动时确保每个风格的智能体在灵矽侧存在，`agent_id` 存入 `style` 表。`skin` 未知或缺失时用默认风格。

**引导智能体**是第五个智能体，不对应皮套，`style_id=welcome`，同样由启动时确保存在。它是"可感"这台核心设备自带的小精灵，名字暂定**小可**（配置项，可改），音色中性、语速慢，提示词同样遵守儿童友好与不诱导留下个人信息。新设备在它这里完成三件事，之后它就退场，孩子之后见到的都是自己的小伙伴：

| 步骤 | 内容 | 必须吗 |
| --- | --- | --- |
| 欢迎 | 自我介绍，说"我带你认识你的新朋友" | — |
| 起名 | 问孩子怎么称呼自己、给小伙伴起什么名字，调 `self.profile.set_names` | 是 |
| 声音登记 | 请孩子跟着说一句话，服务端取这段音频登记声纹，调 `self.voiceprint.enroll` | 否；未获监护人同意、样本取不到或孩子不愿意时跳过，不阻塞交棒 |

**开通是幂等的**（`device.Ensure`），**交棒**（`device.Handoff`）把引导期结束的设备换到风格智能体：

| 档案状态 | 动作 |
| --- | --- |
| 没有档案 | 在灵矽预注册 MAC 并绑定**引导智能体** → 建档案，`stage=fresh` |
| `stage=fresh` | 直接返回，仍由引导智能体接待；此时换 `skin` 无影响，交棒时才按当时的 `skin` 选风格 |
| `stage=named`（名字已记录，尚未交棒） | 重试交棒；不再让孩子重新起名 |
| `stage=ready`，但 `skin` 对应的智能体变了（换皮套） | 在灵矽切换设备绑定的智能体 → 更新档案 |
| `stage=ready` 且一致 | 直接返回 |

交棒 = 按 `skin` 选风格 → 在灵矽把设备切到该风格智能体（不迁移引导期聊天记录）→ 把名字写入新智能体的记忆焦点 → `stage=ready`。会话在 `bridge/linx` 里换智能体重连（握手头 `X-Agent-ID` 决定）。

- **开通失败**：设备收到 `error`，灯变 `muted`，稍后重试。频道对讲不依赖 AI，所以开通失败时设备仍能进频道与好友说话。引导期间设备不询问是否加入区域频道。
- **声纹只登记不绑定**：登记得到的 `speaker_id` 存进档案，但"只回应主人"是智能体级配置，与 D3 冲突，所以不开启；将来改为每台设备克隆智能体时直接复用。登记前必须有监护人对声纹的单独同意（见[开放问题](#11-开放问题)）。
- **记忆**按设备 MAC 隔离（灵矽按 `identify_id` 区分），所以多台设备共用一个风格智能体不会串记忆。
- **认主**在黑客松版指"起名 + 绑定家长"。声纹认主（"只有主人能和这个玩偶说话"）是智能体级配置，与 D3 冲突，默认不做；需要时把"共用风格智能体"升级为"每台设备从风格模板克隆一个智能体"，其他流程不变。
- **"复刻"孩子的声音**（用孩子的音色合成语音）灵矽是否支持尚未确认，见[待验证](linx-integration.md#待验证)；本期只做声纹登记，不做音色复刻。
- **换皮套**后记忆容器是新的。需要时可经 `linxapi` 读写记忆片段把旧记忆搬过去；演示里换皮套很少，先不做。

## 5. 关键时序

### 5.1 设备上线、开通与起名

1. 设备连上 `/ws`，发 `hello(MAC, skin, capabilities, pubkey)`；`gateway` 发挑战、验签后回 `hello.ack`，调用 `app.OnConnect`（[trust.md §2](trust.md#2-设备身份与认证)）。
2. `app` 调 `device.Ensure`。失败 → 下发 `error`，跳过后续步骤。
3. 设备还没绑定家长 → 下发 `bind.code`，设备播报 6 位码；家长在家长端输入并同意后，`device.Bound` 事件让流程继续。绑定前设备的一切上行都被丢弃（[trust.md §3](trust.md#3-绑定家长先开通孩子再认主)）。
4. `app` 调 `bridge/linx.Open`：以该 MAC 和档案里的 `agent_id`（新设备是引导智能体）拨号灵矽，`hello.agent_params` 注入已知的名字与"是否做声音登记"；就绪后向设备下发 `audio.downlink`。
5. `stage=fresh` 时，`app` 调 `Say` 让引导智能体欢迎并请孩子起名。孩子说出名字后，AI 调用 `self.profile.set_names` → `device.SetNames` → `stage=named`，`device` 发 `Named` 事件。
6. （可选）有监护人同意时，引导智能体请孩子跟着说一句话，再调 `self.voiceprint.enroll` → `device.EnrollVoice`；失败只记日志，不影响下一步。
7. `app` 收到 `Named`，等 AI 说完（`OnAIState` 回到 idle）后调 `device.Handoff`：切到风格智能体、写记忆焦点、`stage=ready`；再让 `bridge/linx` 关闭旧会话并以新 `agent_id` 重新 `Open`，由新智能体用孩子起的名字做第一句问候。交棒失败则保持 `stage=named`，下次上线重试。

### 5.2 对 AI 说话

```
设备 ──音频帧──▶ gateway ──▶ app ──▶ voice（路由 = AI）──▶ bridge/linx ──音频──▶ 灵矽
设备 ◀──音频帧── gateway ◀──────────────────────────────── bridge/linx ◀──TTS──── 灵矽
                                                           └ stt/tts 状态 → light、speaker.state
```

不在频道时一直走这条；在频道里要先 `wake`（叫小伙伴的名字）才走这条，一个回合后回到频道。

### 5.3 在频道里和好友说话（含陌生人屏蔽）

```
小朋友 A               voice                 channel     relation       小朋友 B（好友）   小朋友 C（陌生人）
  │ mic.state start+帧 │                      │           │                  │                  │
  │───────────────────▶│ 抢到发言权            │           │                  │                  │
  │                    │ Members(频道) ───────▶│           │                  │                  │
  │                    │◀─────── [A, B, C] ────│           │                  │                  │
  │                    │ AreFriends(A,B)? ────────────────▶│ 是               │                  │
  │                    │ AreFriends(A,C)? ────────────────▶│ 否 → 不转发       │                  │
  │                    │── speaker.state(peer, from=A) ─────────────────────▶│                  │
  │                    │── Opus 帧（每个听者一条有界队列）──────────────────────▶│ C 什么也收不到     │
```

同一频道同一时刻只有一个人说话（对讲机式）；好友说话会打断听者正在播的 AI 语音。

### 5.4 贴近成为好友

规则见 [trust.md §4](trust.md#4-交朋友)，状态机见 [relation](modules/relation.md#状态机)。

1. 两台设备各自上报 `proximity`；`app` 交给 `relation.OnProximity`。
2. 双方都持续靠近 1.5 秒 → `Asked` 事件；`app` 下发 `friend.state{asking}` 与振动，两边的小伙伴各问一句"要和 X 交朋友吗"。
3. 两个孩子 60 秒内都说"好"（AI 调 `self.friends.accept` → `relation.Assent`）。有人说"不要"或超时 → `Dropped`，不打扰家长。
4. 每一侧按自家家长的交友方式：自动放行，或等这一侧家长在家长端批准。两侧都放行 → `Confirmed` → `friend.state{confirmed}`；此后 `voice` 计算听者时对方会被纳入。

### 5.5 进入公园

1. 设备上报 `location`；`zone` 发现进入公园，发出 `Entered` 事件；`app` 让小伙伴问"要加入公园频道吗"。
2. 孩子同意 → AI 调用业务工具 `self.zone.join` → `zone.JoinCurrent` → `channel.JoinZone`。
3. 离开区块时 `zone` 直接 `channel.LeaveZone`，不询问。

## 6. 小伙伴智能体作为频道成员

智能体不是频道的一部分，而是和设备平级的参与者 `agt:<mac>`；频道只管"有哪些参与者"。同意与家长控制见 [trust.md §5](trust.md#5-小伙伴进频道)。

```text
主人："小龙，跟大家讲个笑话"（wake → AI 回合）
  AI 调 self.channel.speak ──▶ app.AgentSpeak
       device.AgentAudience(主人, 频道里其他设备)   自家家长关了 → 失败；对方家长屏蔽的听者记下
       voice.ArmAgent(主人, 屏蔽名单)              20 秒内开口的下一段话算数
  AI 开始说话（OnAIState speaking）──▶ voice 以 agt:<mac> 抢发言权；被占就只有主人听到
       听者 = 同频道、与主人是好友、家长没屏蔽它的设备；speaker.state{source: agent}
  bridge/linx 下发 TTS 帧 ──▶ agentTap：照常给主人设备，同时 voice.OnAgentFrame 转给听者
  AI 说完（OnAIState idle）或主人开口 ──▶ 结束这段发言
```

| 规则 | 怎么做到 |
| --- | --- |
| 只听主人 | 小伙伴的输入只有主人设备的 AI 回合；频道里别家孩子的音频从不送进它的灵矽会话 |
| 只在点名时开口 | 必须先有 `self.channel.speak`，且一次只管一段话 |
| 只到好友 | 听者由 `relation.AreFriends(agt:<mac>, 听者)` 计算，智能体按主人判断 |
| 可与他人同时说话 | 频道允许多人同时说话（服务端混音）；好友开口不会打断小伙伴，主人自己开口则小伙伴让路 |

**接缝**：频道成员、发言人、听者都用 `ParticipantID`；`voice` 只经 `Sink` 收发；`relation.AreFriends` 经 `OwnerDevice` 解析；`bridge/linx` 会话不变，`app` 只在交给它的 `DeviceLink` 外包一层 `agentTap`。

**还没做**：自动参与（不点名就插话）；把频道里的话转给小伙伴当上下文（涉及别家孩子的数据，需要对方家长同意）；小伙伴在频道里说过的话进历史。

## 7. 设备抽象

Web 模拟器与固件各自实现下面七项，其余全在服务端。

| 能力 | 方向 | Web 模拟 | 未来硬件 |
| --- | --- | --- | --- |
| `mic` 麦克风音频 | 设备→服务端 | WebAudio + Opus 编码 | I2S 麦克风 + Opus |
| `speaker` 扬声器音频 | 服务端→设备 | WebAudio 解码播放 | I2S 功放 |
| `light` 灯带 | 服务端→设备 | 3D 发光材质 | LED 灯带 |
| `haptic` 振动 | 服务端→设备 | 玩偶抖动 + 提示音 | 振动马达 |
| `proximity` 靠近发现 | 设备→服务端 | 由地图中的距离生成 | BLE / NFC 扫描 |
| `location` 定位 | 设备→服务端 | 地图中的坐标 | GPS |
| `wake` 唤醒事件 | 设备→服务端 | 点击玩偶或语音唤醒 | 本地唤醒词引擎 |

另有两项设备侧逻辑：语音端点检测（VAD，决定 `mic.state` 的起止）与设备端 MCP 服务（实现设备工具）。

## 8. 隐私规则的执行点

[产品承诺](product.md#5-儿童隐私与安全产品承诺) 与 [AGENTS.md 硬约束](../AGENTS.md) 落在这些地方：

| 规则 | 执行点 | 验证 |
| --- | --- | --- |
| 非好友的音频不转发 | `voice` 计算听者时与 `relation.AreFriends` 求交 | S5 语音验收第 2 条 |
| 非好友不出现在在线列表 | `app` 下发 `presence`、`channel.state` 成员前经 `relation.FilterFriends` 过滤 | S4 验收 |
| 好友要两个孩子同意、两家监护人放行 | `relation` 状态机：asking → pending → confirmed；每侧放行只能由该侧监护人（`parentapi` 校验归属）或该侧家长的自动设置给出 | S15 验收 |
| 未绑定设备不提供服务 | `app.serving` 为假时丢弃全部上行；`gateway` 先验签再登记会话 | S13、S14 验收 |
| 家长只看自家孩子 | `parentapi` 每个接口校验孩子归属 | S10 验收 |
| 灵矽令牌不出服务端 | 只由 `linxapi`、`bridge/linx` 从 YAML 配置文件（`internal/config`）读取 | 代码审查：`web/` 中无令牌 |
| 演示地图不泄露位置 | `/world` 只在演示模式注册 | 默认启动时访问 `/world` 返回 404 |
| 提示词与文案儿童友好 | 风格提示词在 `style` 配置；设备文案走 `ui` 统一文案表 | W7 验收 |
| 声纹与原始音频不入库 | `store` 无对应表；声纹只存在灵矽，档案只存 `speaker_id` | 代码审查 |
| 声纹登记须监护人同意 | `device.EnrollVoice` 先查档案的同意标记，没有则拒绝 | S12 验收 |

## 9. 运行形态

- **后端：** 一个 Go 进程 `palpabled`。路由：`/ws`（设备）、`/api`（家长端）、`/world`（演示模式）、`/healthz`。`main.go` 只读配置并调用 `app` 组装。
- **前端：** Vite 构建的静态页面，开发期把 `/ws`、`/api`、`/world` 代理到后端。
- **厂家后台：** 另一个 Go 进程 `palpable-admin`（独立库、独立账号）与静态页面 `admin/`，见 [factory.md](factory.md)。
- **外部依赖：** 灵矽（地址与令牌来自配置文件的 `linx.ws_url`、`linx.token`、`linx.voiceprint_base`）；SQLite 文件。
- **多设备演示：** 同一页面可开多个"小朋友窗口"，每个是独立的虚拟设备；也可多个浏览器分别接入。

## 13. 扩展与演进

当前形态是**单进程**：频道、发言权、好友缓存都在进程内存里，持久化用 SQLite。这对演示和单区域试点足够，下面是已想清楚的演进路径（**均未实现**，实现前不应在其他文档里当作现状）。

| 阶段 | 瓶颈 | 做法 | 为什么现有架构撑得住 |
| --- | --- | --- | --- |
| 试点（百级设备） | 无 | 现状：单进程 | — |
| 单区域上线 | SQLite 单写、单机故障 | `store` 只暴露仓储接口，换成 PostgreSQL；进程前置负载均衡与健康检查（`/healthz` 已有） | 业务模块只依赖仓储接口，已有假实现 |
| 多区域 / 大规模 | 内存态的频道与发言权 | **按区域分片**：区域频道天然是局部的，同一区域的设备路由到同一实例（粘性连接）；跨实例只共享好友关系与档案 | 频道成员与发言权只存在于 `channel`、`voice`；好友关系在 `relation` 且有缓存边界 |
| 灵矽成为瓶颈 | 每台在线设备一条上游会话 | 只在孩子对 AI 说话时按需建立会话；会话数受会员对话时长上限约束 | `bridge/linx` 已把会话的 Open / Close 收敛为接口 |
| 真实硬件 | 固件资源有限 | 固件只实现 [§7](#7-设备抽象) 的七项能力，Opus 16kHz 单声道 60ms 帧与灵矽对齐 | 协议与设备抽象与 Web 模拟器同源 |

**音频热路径的保护措施**（已实现）

- 每个听者一条有界队列（8 帧，约 480ms）；某个听者消费慢时丢最旧的音频帧，**不影响其他听者**，控制消息从不丢弃。
- 同一频道同一时刻只转发一个人的音频，没有混音开销。
- 热路径不加锁等待、不打印日志；日志只记元数据。
- 每个发言（`Burst`）记录首帧进出时间戳并以 `internal_latency_ms` 输出，目标服务端内部 p95 < 100ms。
- 每个 WebSocket 连接由 `context` 控制生命周期，断开后释放全部 goroutine 与订阅。

**不应指望的事**：单进程方案不提供高可用；演进到多实例前，进程重启会让在线频道状态丢失，设备需重新进入频道。
