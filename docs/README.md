几条约定：

- **完成状态只写在 tasks.md。** 其他文档描述"应该是什么样"，不标进度。
- **协议分两处：** 已生效的在 `protocol/`，计划中的在 [modules.md 的 protocol 一节](modules.md#protocol)；落地时从后者挪到前者。
- **新增决策**写进 [architecture.md 的关键决策](architecture.md#2-关键决策)，带上原因与代价；推翻旧决策时改原条目，不另起一条。

## 阅读顺序

新加入的人：product → architecture → modules 中自己负责的模块 → tasks 中对应的任务包。只做前端的人另读 [设备抽象](architecture.md#7-设备抽象) 与 [前端模块](modules.md#前端模块)。

## 术语表

| 术语 | 含义 |
| --- | --- |
| 设备 | 玩偶里的对讲核心。现在是 Web 模拟器，将来是固件；两者实现同一份协议。身份就是设备 MAC |
| 皮套（`skin`） | 套在设备外的玩偶外观：dragon / rabbit / bear / cat。决定设备默认用哪个风格智能体 |
| 小伙伴 | 孩子眼中的玩偶角色，由孩子起名。它的"大脑"是灵矽智能体 |
| 风格智能体 | 与一种皮套对应的灵矽智能体，同款皮套的设备共用；记忆按设备 MAC 隔离 |
| 引导智能体（小可） | 系统级智能体，不属于任何皮套；只接待还没完成起名的新设备，完成起名（和可选的声音登记）后交棒给风格智能体 |
| 交棒（Handoff） | 设备从引导智能体切换到风格智能体的那一刻，`stage` 由 named 变为 ready |
| 参与者（Participant） | 频道里能说、能听的实体。现在只有设备 `dev:<mac>`，预留智能体 `agt:<mac>` |
| 频道 | 一群参与者的语音空间。区域频道 `zone:<id>` 按位置进入；群 `group:<id>` 靠 4 位码加入 |
| 前台频道 | 一台设备可在多个频道里，但只在前台频道说话和收听 |
| 好友 | 两台设备靠近后经确认建立的关系，是"能否互相听见"的唯一依据 |
| 路由（Route） | 某一刻设备的麦克风音频去 AI 还是去频道 |
| 发言（Burst） | 频道里一个人从开始说到说完的一段话；同一频道同一时刻最多一个 |
| 唤醒（`wake`） | 设备本地检测到孩子在叫小伙伴；在频道里时，只有唤醒后的话才去 AI |
| 设备工具 / 业务工具 | 设备端 MCP 里的两类工具：设备自带的（灯光、振动、拍照）与服务端提供的（建群、起名、入区） |
| 家长（Guardian） | 设备的监护人，确认好友、查看回顾 |
| Web 展示 | 只在演示页面里存在的画面（开箱、公园、地图、手机窗口），不进协议 |
